# API 通知服务（notifier）

面向企业内部业务事件的统一路由与供应商通知服务。业务系统提交事件及发生时的数据，
服务生成固定分发计划，独立投递、追踪和恢复各个供应商任务。

## 核心技术决策

1. **以业务事件接入，明确配置与代码的职责。** 业务方表达发生了什么，由服务决定通知谁。
   路由和简单字段映射通过受限配置完成；复杂鉴权、签名和响应解释由代码适配器承担，
   使配置能力保持可校验、可预测。

2. **冻结业务语义，动态生成发送上下文。** 首次受理时固定事件快照、分发目标、映射结果和协议版本，
   重试沿用原计划。每次发送重新取得有效凭证、生成签名和发送时间，同时保证历史语义一致性与鉴权有效性。

3. **明确存储、消息与缓存职责，以事务 Outbox 支撑可靠投递。** MySQL 保存事件、任务和执行事实，
   RocketMQ 驱动异步调度，Redis 提供缓存和限流。事件、全部任务与首次 Outbox 在同一事务中提交，
   服务依据持久化记录继续发布和恢复。

4. **分别管理三种重试，明确 ACK 与结果确定性。** 发布重试、消费重投和供应商请求重试分别计数、控制预算。
   当前指令的结果或下一步计划持久化后才 ACK；无法确认外部结果且不能安全重发时保留 `UNKNOWN`，
   通过核对或授权人工处置继续推进。

5. **统一错误码，精确表达业务失败原因。** 保留通用 `code`，通过 `reason_code` 区分具体失败条件，
   通过 `category` 聚合分类，并统一维护安全业务消息。事件内容冲突、操作键参数冲突、任务版本变化、
   证据归属错误等都有独立原因码；错误分类、结果确定性和重试资格分别判断。

6. **用明确分层、依赖注入和分级测试控制复杂度。** 首版同仓同进程，各后台角色独立管理生命周期。
   协议转换、业务编排、领域规则与基础设施访问职责明确，通过小接口和 Wire 组装依赖。
   黑盒单测验证业务规则，真实依赖集成测试验证事务、唯一约束、消息协议和故障恢复。

当前提供后端 HTTP API，使用 `mock-json/1` 适配器验证供应商协议与故障场景；真实供应商需实现相应适配器。

## 本地运行

依赖 Go 1.26.2、Docker 和 Docker Compose，从仓库根目录执行：

```sh
# 启动基础设施，等待各依赖就绪后初始化
docker compose up -d mysql redis rocketmq-namesrv rocketmq-broker rocketmq-proxy
make migrate-up
make topics
make build
./bin/notifier
```

另开终端执行 `./bin/mockvendor` 启动模拟供应商。通知服务地址为 `127.0.0.1:8080`，
通过 `/healthz` 检查存活、`/readyz` 检查依赖就绪。
配置来自环境变量，程序不自动读取 `.env`；完整配置与初始化说明见 [本地开发与验证](./docs/development.md)。

```sh
make test
make vet
make race
make build
```

真实依赖集成测试的运行方式及 RocketMQ 客户端的已知 race 限制见 [验证说明](./docs/development.md#验证)。

按捕获时已经落盘的内容逐字节保留，未删改。ZIP 内的 `manifest.json` 记录来源、捕获时间和文件 SHA-256；
外部校验值见 [ai-sessions.zip.sha256](./ai-sessions.zip.sha256)。

```sh
shasum -a 256 -c ai-sessions.zip.sha256
```

后续新增消息需重新导出；脚本与校验方法见 [会话归档说明](./docs/development.md#ai-会话记录)。
